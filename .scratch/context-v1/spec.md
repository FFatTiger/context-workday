# Context v1 功能规格

术语以 `CONTEXT.md` 为准，界面以 `docs/design/ui.md` 为准，决策背景见 `docs/adr/`。技术栈见 `AGENTS.md`；数据结构以 `src/db/schema.ts` 为准，接口形状以 `src/api-types.ts` 为准，代码和本文冲突时以代码为准并在票里说明。

## 问题

我的工作散落在群聊、私聊、日程和邮件里。客户端的 IM 只保留 7 天，邮件只保留 3 个月。到写周报、做复盘时，我想不起这段时间干了什么，也找不到当时的原话。现有原型页面难看，逻辑也偏了（做了图谱等不需要的东西）。

## 方案

- 定时备份全部原文，永久保存在本机。
- 每小时为有记录的小时生成小时摘要；每天生成日结，并增量更新本周、本月；每月增量更新本年。
- 每天打开"今天"页，左边是当天不规则的小时时间线，右边是今天、本周至今、本月至今三张摘要卡。
- 任何条目都能点开证据链，一路追到原文；原文丢了就显示 AI 当时的概述和丢失原因。
- 每个摘要保留全部版本，可以逐条对比。
- 备份、定时任务都有独立页面，能看状态、能调整。

## 实现决定

### 1. 口径：哪些原文进入摘要

参与形态和判定方法如下：

| 形态 | 判定 |
|---|---|
| 我开口 | 消息的发送者是我 |
| @我 | 消息 @ 了我本人。@所有人不算 |
| 回复我 | 消息引用回复了我的某条消息 |
| 私聊 | 一对一会话里的任何消息 |
| 定向发给我 | 群里由客户端标记为定向发给我的消息。系统播报不算 |

- **参与会话**以"会话 × 小时"为单位：该小时内，这个会话里有任一条消息满足一种开启的形态，这个会话该小时的全部消息就都进入输入。
- **日程**：我是组织者，或者我是参会人且没有拒绝。按开始时间归到那个小时。全天日程不计入。
- **邮件**：我发出的邮件，或者收件人（To）里有我的邮件。抄送、密送不算。按收发时间归到那个小时。
- **降噪**：系统消息（入群、退群、撤回提示等）不进输入。同一会话同一小时里内容完全相同的转发，只保留一条。
- **上下文**：每个参与会话额外附上本小时之前最近 10 条消息，标为"仅供理解"，不能被引用。
- **统计**：每个小时记录"全部消息数"和"与我有关的原文数"，今天卡片的页脚要用。
- 设置里每种形态、日程、邮件各有一个开关，默认全开。每次运行开始时读取当时的开关；改动只影响之后的生成。

### 2. 定时任务

| 任务 | 默认时间 | 允许范围 | 做什么 |
|---|---|---|---|
| 小时摘要 | 每小时第 5 分 | 第 1~30 分 | 处理所有待处理小时 |
| 日结 | 每天 20:30 | 12:00~23:59 | 处理当天：核对迟到消息、生成日结、增量更新周和月 |
| 补跑 | 每天 00:30 | 00:00~05:59 | 对前一天补跑；遇到周期结束就收尾 |
| 年摘要 | 每月 1 日 03:00 | 1~28 日，补跑之后 | 把上个月的最终版并入本年 |
| IM 备份 | 每天 02:00 | 任意 | 备份全部会话的新消息 |
| 日程备份 | 每天 02:00 | 任意 | 备份新增和变更的日程 |
| 邮件备份 | 每周日 03:00 | 任意 | 备份新邮件（含已发送） |

通用规则：

- 每个任务都按"待处理清单"工作，而不是只处理"这一刻"。所以错过的运行（电脑睡眠、程序关闭、客户端没开）会在下一次运行或程序启动时自动补上。程序启动时，每个任务立即检查一次待处理清单。
- 同一个任务同一时刻只跑一个实例。同一个摘要系列的生成也必须串行。
- 每次运行都写一条运行记录：计划时间、开始和结束时间、结果（成功 / 跳过 / 失败 / 中断）、一句说明，以及产出的版本。
- 程序退出时正在跑的任务，下次启动时记为"中断"，由待处理清单重新处理。

### 3. 小时摘要

**待处理小时**：过去 7 天内已经结束、还没有"成功"或"跳过"记录的小时。按时间从早到晚逐个处理。只追 7 天，是因为客户端的原文只保留 7 天。

操作逻辑（单个小时）：

1、从客户端读取该小时内全部会话的消息、开始时间落在该小时的日程、该小时收发的邮件；
2、按口径筛出参与会话，取出每个参与会话在该小时的全部消息并降噪，附上上下文消息；再加上我参加的日程和与我有关的邮件；
3、如果没有与我有关的原文，记为"跳过"，结束；
4、调用大模型，要求最多输出 3 个条目，每条一句话（建议 40 字以内，最多 80 字），并写明引用的原文编号；
5、校验引用：只保留指向本小时输入原文的引用，引用了上下文消息或不存在的编号就去掉；去掉后没有引用的条目丢弃；
6、条目超过上限时，带着错误提示重试一次；仍然超出，就按顺序保留前 3 条；
7、保存为该小时的新版本（全量生成），连同条目、引用和统计一起原子写入；
8、如果这个小时之前已有版本，给引用过它的日结标"上游已变更"。

### 4. 日结

日结任务处理"今天"，操作逻辑：

1、先把当天所有待处理小时跑完；
2、**迟到核对**：对当天每个已有小时摘要的小时，重新数一遍与我有关的原文；比生成时多了，就重跑这个小时，触发方式记为"迟到重跑"；
3、当天如果一个小时摘要都没有，记为"跳过"，结束；
4、当天还没有日结时，全量生成，引用当天的小时摘要条目；已经有日结时，只把上次之后新出的小时摘要版本作为输入，做增量生成；没有新输入就跳过；
5、条目上限 6；
6、用新的日结版本增量更新本周和本月的摘要（见第 5 节）；
7、运行记录的说明形如"生成 日结 v1 · 本周 v4 · 本月 v16"。

"今天"卡片上的"立即生成"按钮，就是立即对今天执行一次上面的流程。

### 5. 周摘要、月摘要：增量更新、补跑、收尾

- 一周是周一到周日，标签用 ISO 周号（"第 44 周"）；月按自然月。跨月的周不拆开。
- **增量更新**：输入是上一个版本的条目（带编号），加上这次新的日结条目。大模型逐条给出：保留、修改（给出新文本）、删除、新增（给出文本）。新增条目的编号由系统分配，编号在这个系列里永不复用。
  - 修改的条目保留原有引用，再追加本次新引用；
  - 新增的条目必须引用本次输入里的日结条目；
  - 条目上限：周 8、月 10、年 12，超限处理同小时摘要。
  - 这个周期还没有任何版本时，第一次就是从空开始的增量（等同全量）。
- **补跑**（每天凌晨）：
  0、先找出过去 7 天里（不含今天、昨天）有小时摘要但还没有日结的日子，按时间先后逐天执行日结流程（客户端断开几天后恢复时会出现这种日子）；
  1、检查前一天日结之后有没有新产生的小时摘要版本；有，就对前一天的日结做增量生成，并再增量更新周和月；没有就跳过；
  2、如果前一天是周日，对上周做收尾；如果前一天是月末，对上个月做收尾。
- **收尾**：不参考上一个版本，用该周期全部日结的最新版本做全量生成，存为新版本并标"最终版"。之后这个周期不再增量更新。
- 已收尾的周期，如果周期内的下层又出了新版本（包括新补出的日结），同样标"上游已变更"。手动重建会再生成一个最终版。

### 6. 年摘要

每月 1 日运行。先确认上个月已经收尾，没有收尾就先收尾。然后用上个月的最终版月摘要条目，对本年做增量更新，引用的是月摘要条目。1 月 1 日并入 12 月之后，那一版就是上一年的最终版。

### 7. 条目与证据链

- 引用关系：小时条目 → 原文（IM 消息、邮件、日程）；日结条目 → 小时条目；周、月条目 → 日结条目；年条目 → 月条目。
- 引用指向下层摘要的**某个具体版本里的某个条目**，所以下层出了新版本后，旧引用依然能打开。界面会提示"引用的是 v1，当前最新 v2"。
- **原文是否可用**在展示时判断：先查本机备份，再查客户端，都找不到就判定为丢失，记下丢失原因，以后不再反复查客户端。丢失原因有三种：
  - 备份缺口：那天备份失败，且已超过客户端保留期；
  - 备份时已不存在：备份时客户端里已经没有这条（例如被撤回）；
  - 超过保留期未备份：邮件超过 3 个月仍未备份。
- **降级**：小时条目引用的原文里，只要有一条丢失，这个小时条目就算"已降级"。展示时用该小时条目自己的文本作为"AI 当时概述"，并附上生成时间和丢失原因（ADR-0002）。同一个小时条目下丢失多条原文时只显示一个降级框，写明"N 条原文已丢失"，其余可用原文照常列出。客户端未连接、暂时查不到的原文显示为"原文暂不可读"，不算降级。
- **计数**：
  - "证据 n"：直接引用的下层条目数；
  - 小时条目上按类型显示"原文 n / 邮件 n / 日程 n"；
  - "降级 n"：证据链下面已降级的小时条目个数。
- 证据链按需展开：默认只展开直接证据；"展开到原文"一次最多显示 50 条原文，超出部分显示"还有 N 条"。

### 8. 版本

- 每个摘要系列由"层级 + 周期"确定。版本号 v1、v2……依次递增；版本生成后不再改动；所有版本永久保留。
- 每个版本记录：生成时间、触发方式（定时 / 补跑 / 收尾 / 手动 / 迟到重跑）、生成方式（增量 / 全量）、用了哪些下层版本、模型名称；小时版本还要记录统计数。
- **上游已变更**：版本生成之后，它用过的某个下层系列又出了新版本，就标上这个状态。同一系列用最新输入生成新版本后，这个状态清除。
- **手动重新生成**：任何层级都可以，一律全量生成，用的是当前最新的下层版本。重新生成后，引用它的上层标"上游已变更"。
- **对比两个版本**：两个版本属于同一条增量链（条目编号相同）时，逐条显示修改（旧文本 → 新文本）、新增和删除；只要其中有一个是全量生成的版本，就改为按全文对比，左右两列显示。

### 9. 备份

- 范围：客户端能读到的全部 IM 会话和全部消息（包括没参与的会话和系统消息）、全部日程、全部邮件（含已发送）。按原文 ID 去重；永久保存，不清理。
- 每个来源维护一个**水位**，即最后一次成功备份到的时间点。每次运行都读取水位之后、客户端里还有的全部数据，所以失败后的重试能把积压一次补齐。

操作逻辑（一次备份运行）：

1、读取该来源水位之后的全部新数据；
2、按原文 ID 去重后写入本机；
3、**核对**：对涉及的每一天，比较客户端条数和本机条数；
4、全部一致，把水位推进到最新，记为"成功"；有不一致的日子，水位只推进到最早不一致那天之前，记为"部分成功"，并写明是哪几天；
5、写运行记录：新增条数、耗时、结果、失败原因；
6、失败或部分成功时，每小时自动重试一次，直到成功。

- **每日覆盖状态**：已备份；等待备份（还没到这一天结束后的第一次备份计划时间，不算缺口、不告警）；缺口·可补救（过了计划时间还没备份，但仍在客户端保留期内）；缺口·已过期（没备份，且已超过保留期）；无数据（安装前）。核对出过不一致的日子直接算缺口，不等计划时间。
- **告警**：IM 只要有"缺口·可补救"的日子，所有页面顶部就显示告警横幅"IM 备份失败 · 还剩 N 天可补救"，N = 最早那天距离超过 7 天还剩的天数。邮件在剩余天数 ≤ 14 天时告警。
- **完整性校验**：结果取最近一次 IM 备份的核对结果，显示在存储卡片上。
- "立即备份"会依次运行三个备份任务。

### 10. 搜索

- 范围：所有摘要系列当前版本的条目，加上本机备份里的原文。今天还没备份的原文搜不到，空结果时要提示"今天的原文会在下次 IM 备份后可搜"。
- 匹配方式：关键词子串匹配，多个词之间用空格分隔、按"与"组合。
- 筛选：
  - 时间：今天 / 本周 / 本月 / 全部；
  - 来源：摘要 / IM / 邮件 / 日程，多选；
  - "只看与我有关"：默认开启，开启时原文只返回与我有关的原文。是否与我有关，在备份时按当时的口径算好，存成标记。
- 排序：按时间倒序，每页 50 条。
- 点击结果：
  - 小时条目或日结条目 → 跳到"今天"页对应日期，高亮对应卡片；
  - 周、月、年条目 → 跳到回顾页的对应系列，高亮该条目；
  - IM 原文 → 打开上下文弹窗，弹窗里可以"去时间线"；
  - 邮件、日程 → 打开详情弹窗。

### 11. 设置

- **参与口径**：8 个开关（五种形态、我参加的日程、我发出的邮件、收件人是我的邮件），并附上"只影响之后生成"的说明。
- **模型**：显示模型名称和地址（读仓库现有配置；仓库已有编辑入口就复用）；提供"测试连接"，返回成功与否和耗时。**数据去向**按地址推导：本机地址（localhost、127.0.0.1、::1）显示"仅本机"，其他地址显示"发送到 <主机名>"。
- **演示脱敏**：一个全局开关，侧栏也有同一个开关，状态持久保存。只影响显示，不改数据，也不影响生成。规则：
  - 人名：保留姓，其余每个字换成"*"（"李敏"→"李*"，"王总"→"王*"）。人名来源是通讯录；
  - 群名：换成"群 1""群 2"……同一个会话编号固定，编号持久保存；私聊显示为"私聊 · 王*"；
  - 金额：带货币单位的数字（元、万、亿、¥、$ 等）换成"***"，百分比和时间不变；
  - 邮箱地址：@ 前面只保留第一个字符。

### 12. 数据结构（逻辑实体）

按仓库现有的存储方式落地，以下只列需要的信息。

**IM 消息**：客户端消息 ID、会话 ID、发送者 ID 和名称、发送时间、文本内容（非文本消息记类型和描述）、是否系统消息、@列表（含是否 @所有人）、引用回复的消息 ID、是否定向发给我、是否与我有关（备份时算好）、备份时间。

**会话**：会话 ID、名称、类型（群 / 私聊）、脱敏编号。

**邮件**：邮件 ID、主题、发件人、收件人、抄送、时间、纯文本正文、文件夹、是否与我有关、备份时间。

**日程**：日程 ID、标题、开始和结束时间、是否全天、组织者、参会人及我的响应状态、地点、备注、是否与我有关、备份时间。

**原文可用性**：原文类型和 ID、状态（可用 / 丢失）、丢失原因、判定时间。

**备份运行**：来源、触发方式（定时 / 重试 / 手动）、开始和结束时间、结果（成功 / 部分成功 / 失败）、失败原因、新增条数、运行后的水位、逐日核对结果（日期、客户端条数、本机条数）。

**摘要系列**：层级（小时 / 日 / 周 / 月 / 年）、周期键（例如 2026-10-29T09、2026-10-29、2026-W44、2026-10、2026）、当前版本号、是否最终版、是否上游已变更、下一个条目编号。

**摘要版本**：所属系列、版本号、生成时间、触发方式、生成方式、输入版本列表（下层系列 + 版本号）、模型名称、统计（仅小时：全部消息数、与我有关原文数）。只保存成功的版本；生成失败记在系列的状态和失败原因上（`series.state`、`series.last_error`），以及任务运行记录里，不占版本号。

**条目**：所属版本、条目编号（系列内固定）、在本版中的位置、文本、本版操作（保留 / 修改 / 新增）。删除的条目不出现在新版本里，对比时按编号推导出来。

**证据引用**：所属条目（版本 + 编号）、目标类型（下层条目 / IM 消息 / 邮件 / 日程）、目标（下层条目用"系列 + 版本 + 编号"，原文用原文 ID）、是否本版新增的引用。

**定时任务**：任务名、是否启用、时间规则（类型 + 参数）、上次运行、下次运行。

**任务运行记录**：任务、处理对象（例如"小时摘要 · 19:00"）、计划时间、开始和结束时间、结果（成功 / 跳过 / 失败 / 中断）、触发（定时 / 手动 / 启动补跑）、说明、产出的版本列表。

**设置**：口径开关、演示脱敏开关、脱敏编号映射。

### 13. 接口（页面需要的数据和操作）

接口的路径和格式按仓库风格定，下面写每个接口的输入、输出和关键操作逻辑。

1. **某天时间线**
   - 输入：日期。
   - 输出：有记录的小时列表（每个小时：当前版本的条目及各类证据计数、版本号、生成时间、触发方式、状态 正常 / 生成中 / 失败）；空档区间；当天还要返回当前时间和下次小时摘要的时间。
2. **摘要卡片**
   - 输入：层级 + 周期键；或者日期 + 层级，由后端推出所在周期。
   - 输出：状态（未生成 / 生成中 / 已生成 / 失败）、计划生成时间（未生成时）、当前版本号、生成时间、生成方式、是否最终版、是否上游已变更、条目（文本、本版操作、证据数、降级数）、输入统计（"依据 N 份日结"）；日结还要返回当天的消息统计。
3. **证据链**
   - 输入：条目（系列 + 版本 + 编号）、要展开的节点。
   - 输出：树节点（类型、层级、日期或时间、文本或原文内容、可用性、降级信息、"引用的是 vX，当前最新 vY"提示）和汇总计数。
   - 操作逻辑：1、读取条目的引用；2、下层条目引用直接返回该版本的条目；3、原文引用按"先本机、后客户端"判断可用性，丢失的记下原因；4、小时条目只要有原文丢失，就返回降级信息（AI 当时概述 = 该条目文本、生成时间、原因）；5、汇总原文、邮件、日程和降级的数量。
4. **原文上下文**
   - 输入：IM 消息 ID。
   - 输出：同一会话中该消息前后各 30 分钟的消息，被引用的消息加标记。
5. **版本列表**
   - 输入：系列。
   - 输出：每个版本的版本号、时间、触发方式、生成方式、变更计数（新增 / 修改 / 删除）、是否最终版、输入说明（例如"并入周四日结"）。
6. **版本对比**
   - 输入：系列、版本 A、版本 B。
   - 输出：逐条差异，或"全文对比"标记加两个版本的完整条目。
7. **周期的下层输入**
   - 输入：系列。
   - 输出：下层周期列表（周 → 7 天；月 → 当月每一天；年 → 12 个月）。每项包括：日期或月份、前两个条目的文本、状态（已生成 / 未生成 / 未来 / 无记录），以及它被并入到哪个版本。
8. **重新生成**
   - 输入：系列。
   - 操作逻辑：1、校验周期不在未来；2、校验该系列没有正在进行的生成，有就返回"正在生成"；3、用最新的下层版本全量生成（小时级从原文生成）；4、原子保存新版本；5、给引用它的上层系列标"上游已变更"；6、返回新版本号。
9. **立即生成日结**：对今天执行一次日结任务，返回运行记录。
10. **定时任务列表和修改**
    - 修改的操作逻辑：1、按任务类型校验时间规则和允许范围，不合法时返回具体提示；2、保存；3、重新计算下次运行时间并返回。
11. **立即运行任务**：同一个任务正在运行时拒绝；否则开始运行，返回运行记录 ID。
12. **运行记录**：可按任务和结果筛选，分页。
13. **备份状态**：三个来源的状态、累计数量、客户端保留期、频率、上次和下次运行、当前是否在备份及进度。
14. **备份覆盖**
    - 输入：来源、天数（IM 和日程默认 60，邮件默认 120）。
    - 输出：逐日状态、7 天窗口内未备份的天数，以及受缺口影响的降级条目数。
15. **受缺口影响的条目**：返回被降级的小时条目，以及引用了它们的上层条目列表。
16. **备份记录**：分页，可按来源和结果筛选。
17. **立即备份**：依次运行三个备份任务。
18. **存储统计**：总占用、原文占用、摘要与版本占用、最近一次完整性校验的时间和结果。
19. **搜索**
    - 输入：关键词、时间、来源、是否只看与我有关、页码。
    - 输出：结果列表（类型、来源说明、时间、带高亮位置的片段、跳转目标）和总数。
20. **设置读取和保存**：保存口径开关、演示脱敏开关；"测试连接"单独一个接口。
21. **全局状态**：返回 IM 备份最近一次的结果和时间、今天日结的状态、告警（来源、剩余天数）、侧栏的已备份天数。

### 14. 异常处理

- **客户端没开或接口报错**：摘要任务记为失败，下一次运行时从待处理清单里补；备份任务每小时重试，并触发告警。
- **大模型调用失败或超时**：间隔 10 秒、30 秒、90 秒重试 3 次；仍失败就把这个版本记为失败。时间线上显示"生成失败 · 重试"卡片，摘要卡显示失败状态和重试按钮。
- **模型输出格式不对**：带着错误提示重试一次；仍然不对，就丢弃不合规的条目；一个有效条目都没有时，按失败处理。
- **写入失败**：一个版本连同它的条目、引用要么全部写入，要么全部不写，不留半个版本。
- **周期在未来**、**任务时间不合法**：直接拒绝，返回具体提示。
- **时区**：所有周期按 Asia/Shanghai 划分。

## 测试决定

- 只测对外行为。最高的测试接缝是"生成流水线 + 假客户端 + 假模型"：给定原文和模型的固定输出，断言产生的版本、条目、引用和状态。备份用假客户端测水位、核对和覆盖状态。测试设施沿用仓库现有的。
- 必测场景：
  1. 没有参与的小时被跳过，不产生版本。
  2. 参与会话里别人没 @我 的拍板消息可以被引用；只有 @所有人 的会话不算参与。
  3. 引用无效的条目被丢弃；引用了上下文消息的引用被去掉。
  4. 日结前发现迟到消息，会重跑该小时，产生小时 v2，日结引用的是 v2。
  5. 周摘要增量更新：编号不变，修改的条目保留旧引用并追加新引用，删除的条目在对比里显示为删除。
  6. 补跑：只有在日结后出现新小时摘要时才产生日结 v2，并让周和月各加一个版本。
  7. 周一凌晨的补跑对上周做收尾，产生最终版；月初同理；年摘要用的是上个月的最终版。
  8. 上游已变更的标记在下层重跑后出现，上层重建后消失。
  9. 原文在本机和客户端都找不到时，返回降级信息和正确的原因。
  10. 备份失败时水位不动，下次成功时把积压一次补齐；核对不一致记为部分成功；覆盖状态（可补救 / 已过期）和告警天数计算正确。
  11. 模拟电脑睡眠 3 小时后启动，3 个小时摘要按时间先后补齐；超过 7 天的小时不再追。
  12. 演示脱敏在各个接口的展示结果中一致，同一个群的编号固定。
- 界面：每个页面都覆盖正常、加载中、空、失败四种状态；布局对照效果图检查。

## 验收口径

- **今天页**：
  - 打开就显示当天时间线和三张摘要卡；
  - 没有记录的小时不出现卡片，连续的空档合并成一行虚线说明；
  - 卡片上的证据数和证据抽屉里的数量一致。
- **立即生成日结**：日结生成前显示计划时间和"立即生成"；点击后出现日结 v1，本周和本月的版本号各加 1。
- **证据链**：
  - 任意条目都能逐层展开到原文；
  - 原文丢失的地方显示虚线框"原文已丢失 · 降级为 AI 当时概述"，带生成时间和原因。
- **回顾页**：
  - 周、月的版本历史和运行记录一致；
  - 选中某个版本时，和上一版的差异逐条显示；
  - "上游已变更"的摘要有标记和重建入口，重建后标记消失，版本号加 1。
- **备份**：
  - 让 IM 备份失败后，所有页面顶部出现告警，并显示剩余天数；
  - 恢复之后积压被补齐，告警消失，覆盖条变绿。
- **任务页**：
  - 修改时间后"下次运行"立即更新；
  - 不合法的时间（例如把日结设到 03:00）会提示，并且不保存；
  - 停用的任务不再运行。
- **错过补跑**：程序关闭 3 小时后重新启动，错过的小时摘要按时间顺序补齐，运行记录的触发方式标为"启动补跑"。
- **搜索**：关键词能命中摘要和已备份的原文；点击结果能跳到对应位置并高亮。
- **设置**：
  - 数据去向和实际的模型地址一致；
  - 演示脱敏打开后，所有页面的人名、群名、金额都被替换，关闭后恢复。

## 实施顺序

每一步结束时，按上面的验收口径自测通过再进入下一步。

1. 数据结构和三个备份任务（水位、核对、重试、覆盖状态）、备份页、告警横幅。
2. 口径和小时摘要（生成、校验、引用）、今天页的时间线、证据抽屉（小时条目 → 原文，含降级）。
3. 日结、周和月的增量更新、补跑、收尾、年摘要、版本和"上游已变更"、今天页右侧的三张卡、回顾页。
4. 任务页（配置、立即运行、运行记录）、启动补跑。
5. 搜索、设置、演示脱敏。
6. 对照 `docs/design/ui.md` 补齐各页面的加载、空、失败状态和交互细节。

## 范围之外

- 消息、日程、邮件之间的细粒度关联，以及事项和图谱（ADR-0004）。
- 手动修改摘要内容。
- 移动端，以及宽度小于 1280 的布局。
