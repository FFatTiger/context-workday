# 摘要按条目做增量更新

周摘要和月摘要每天、年摘要每月，都是用上一个版本加上新完成的下层摘要来生成新版本。增量更新以"条目"为单位：每个条目有固定编号，AI 每次逐条给出保留、修改、新增或删除，以及新引用了哪些下层条目。周期结束时做一次重建，作为最终版。下层出了新版本时，上层只标记"上游已变更"，不连锁重算。

如果每次整段重写，版本之间只能做全文对比，而且每轮合并都可能把证据引用弄丢。

## 考虑过的做法

- 每次整段重写：实现简单，但证据链和版本对比都不稳定。
- 下层一变就自动连锁重算：数据总是最新的，但一次手动重跑会触发多层大模型调用，版本历史也会被连锁产生的版本淹没。

## 后果

- 增量合并会累积偏差，靠收尾重建来抵消。
- 修改过的条目保留原有引用，再追加本次的新引用，证据只增不丢。
- 上层可能停在"上游已变更"状态，界面要显示出来，并提供重建入口。
