# 产品说明

## 背景

我的工作几乎都在企业 IM 里：群聊推进、私聊对齐、日程约时间、邮件走流程。到写周报、做复盘的时候却想不起来，主要有三个原因：

- 一件事散在好几个群、私聊和日程里，没有一处能看全；
- 客户端的 IM 只保留 7 天，邮件只保留 3 个月，过期就没了；
- 群里消息多，跟我有关的只有几条。

本机客户端能程序化读取会话、邮件、日程和通讯录，数据不出机器；大模型足够便宜，能把零散对话压成几句结论。

## 要做成什么样

每天打开后台，看到三样东西：**今天干了啥、这周到目前干了啥、这个月到目前干了啥**。主视图是当天按小时排列的时间线，没记录的小时不出现。

任何一个条目都能点开证据链，往下追到原文。原文丢了，证据链停在 AI 当时写的概述上，并说明原因。摘要保留全部历史版本。备份和定时任务都能看到、能调整。

当前阶段的首要用途是做能演示的原型：任何人 10 秒内能看懂它是什么，并且觉得好看。

## 整体逻辑

```
客户端原文 ──(备份：IM/日程每天，邮件每周)──► 本机永久备份（全部会话）
     │
     └─(按口径筛出与我有关的原文)─► 小时摘要 ─► 日结 ─┬─(增量)─► 周摘要
                                                    ├─(增量)─► 月摘要 ─(每月增量)─► 年摘要
                                                    └─ 次日补跑 / 周期收尾重建
证据链方向相反：年 → 月 → 日 → 小时 → 原文
```

规则细节见 `.scratch/context-v1/spec.md`，页面见 `docs/design/ui.md`。

## 三条原则

1. **口径优先**："跟我有关"判错了，后面全错。口径定义见 `CONTEXT.md` 的"口径"一节。
2. **每个条目都要能被质询**：引用不上证据的条目不允许出现在页面上。
3. **数据去向如实说明**：原文只存本机；模型调用发往哪里，就在设置页如实显示哪里。

## 与原背景文档的差异（以本文档包为准）

| 原背景文档 | 现在 |
|---|---|
| 图谱页、会话关联 | 作废，见 ADR-0004 |
| 活动片段（片段 → 小时） | 取消；小时摘要直接按"会话 × 小时"取原文 |
| 参与按单条消息判定 | 改为按会话判定，见 ADR-0003 |
| 页面：今天、报表、搜索、图谱、设置 | 页面：今天、回顾、搜索、备份、任务、设置 |
| 时间金字塔：片段 → 小时 → 日 → 周 → 月 | 小时 → 日 → 周 / 月（增量）→ 年（增量），带版本 |
| 备份未单独成为功能 | 备份是核心功能，有独立页面和定时任务 |
